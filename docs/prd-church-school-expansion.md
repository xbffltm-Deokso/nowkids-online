# 교회학교 부서 확장 PRD

2026-11-14 기준 · 원본 문서: Claude Docs "교회학교 8개 부서 확장 PRD" (이 파일은 다른 컴퓨터에서 이어서 작업하기 위한 사본)

## 배경과 목표

교육1부 8개 부서가 하나의 웹앱으로 출석 체크, 통계, ch2ch 반영, 진급, 주일보고서 작성을 처리하고, 교육2부 3개 부서는 같은 앱에서 주일보고 특이사항을 입력하는 것이 목표입니다. 지금 앱은 소년부 한 부서에 맞춰져 있어, 부서·권한·설정을 새로 넣는 구조 개편이 필요합니다.

**왜 확장하나**

- 부서마다 구글 시트, ch2ch 수기 입력, 종이 출석부가 섞여 있어 전체 출석 현황을 한눈에 볼 수 없습니다.
- 소년부에서 검증한 흐름(교사 출석 체크 → 관리자 통계 → ch2ch 분기 반영 → 연말 진급)은 모든 부서가 똑같이 반복합니다.
- 주일보고서는 매주 양식을 복사해 숫자를 손으로 옮겨 적고 있어, 출석 데이터로 자동 작성할 수 있습니다.
- 아동 개인정보가 여러 시트에 흩어져 있고 일부는 링크 공개 상태라, 한곳에서 권한을 두고 관리할 필요가 있습니다.

**성공 기준 (안)**

| 기준 | 목표치 (안) | 측정 |
| --- | --- | --- |
| 부서 사용률 | 교육1부 모든 부서가 매주 출석 입력 | 주일별 기록이 있는 부서 수 |
| 출석 입력 완료율 | 주일 당일 재적 대비 기록 90% 이상 | 출석 통계의 기록 인원 / 재적 |
| 주일보고서 | 부서 교역자가 버튼 한 번으로 시트 작성, 손으로 옮겨 적는 숫자 0개 | 부서별 작성 버튼 사용 여부 |
| ch2ch 반영 | 부서당 분기 1회, 학년별 북마클릿 실행으로 끝남 | 부서 담당자 확인 |
| 개인정보 관리 | 개인정보가 담긴 공개 링크 시트 0개 | 구글 드라이브 공유 설정 점검 |

## 현재 시스템 현황 (As-Is)

현재 앱(Next.js + Neon Postgres + Drizzle, Vercel 배포)은 소년부 전용이며, 아래 항목이 모두 "부서가 하나"라는 가정 위에 만들어져 있습니다.

| 영역 | 현재 | 확장 시 문제 |
| --- | --- | --- |
| 학년·반 | 코드에 4.믿음·5.소망·6.사랑, 1~4반 고정 (`src/utils/grades.ts`), 학생에 학년 문자열·반 번호 저장 | 부서마다 학년·반이 다르고, 부서 개편이 예정되어 있음 |
| 학생 ID | 일부는 `학년_반_번호_이름`, 새 학생은 UUID | 부서 간 동명이인, 이동 시 혼동 (ID는 유지하되 의미를 두지 않음) |
| 접근 권한 | 페이지·조회 API 공개, 관리자 비밀번호 1개(`APP_PASSWORD`, 미설정 시 임시 비밀번호) | 부서별 분리 불가 |
| 출석 저장 | 교사 화면이 반 전체 학생을 결석 기본값까지 한꺼번에 덮어씀 | 여러 선생님이 동시에 저장하면 서로의 입력을 지움 |
| 날짜 | 서버에서 "이번 주 일요일"을 계산 | 서버가 UTC라 한국 일요일 0~9시에는 지난주로 잡힐 수 있음 |
| 통계·출석그룹 | 전체 재적 기준 52주 계산 | 부서별로 나눠야 함 |
| ch2ch 연동 | 북마클릿 + 공개 API `/api/ch2ch?grade=4` (학년 숫자로 대응) | 다른 부서는 학년 숫자만으로 구분 불가 |
| 진급 | 4→5→6학년, 6학년은 "진급" 상태 | 부서 간 이동이 없음 |
| 주일보고서 | 별도 구글 시트, 양식 복사 후 수기 입력, 재적 탭 수식 | 앱과 연결되지 않음 |
| 개발 환경 | 로컬 개발도 운영 DB 사용 | 시험이 실제 데이터를 바꾸거나 개인정보를 노출할 위험 |

## 조직과 범위

**교육1부 (8개 부서, 학생 약 300명)**: 통합미취학부(2~7세, 10시 예배), 영유아부, 유치부, 통합아동부(8~13세, 10시 예배), 유년부, 소년부, 중등부, 고등부. 통합 부서 외 6개는 12시 예배입니다. **교육1부는 개편이 예정되어 있어**(예: 통합 부서 폐지 후 미취학 1부·2부), 부서·학년·반은 코드에 넣지 않고 모두 설정으로 관리합니다.

**교육2부 (3개 부서, 보고 전용)**: 원더풀 시니어, 장년교육부, 문화홍보부. 학생·출석 없이 주일보고 특이사항만 입력합니다.

- 같은 나이라도 예배 시간에 따라 부서가 나뉘므로 나이로 부서를 자동 배정하지 않습니다. 학년 중간의 부서 이동(10시 ↔ 12시)을 지원합니다.
- 통계는 **현재 부서 기준**으로 봅니다. 부서를 옮긴 학생의 지난 출석은 새 부서 통계에 함께 잡힙니다.
- **반은 교사가 출석을 쉽게 표시하기 위한 묶음일 뿐**입니다. 주일보고서는 연령별 인원수만 보고하므로 반과 무관합니다.
- **범위에 포함**: 주일보고서의 헌금 금액 입력(보고용). **범위에서 제외**: 헌금 회계·정산, 장년부 출석, 문자 발송, 학부모용 화면, 교역자동정란.

| 역할 | 누구 | 할 수 있는 일 | 접속 방법 |
| --- | --- | --- | --- |
| 전체 교역자 | 교육 담당 교역자 | 모든 부서 설정·DB 수정, 진급, 개인정보, 교역자 계정 관리, 전체 통계·주일보고서 | 교역자 계정 로그인 |
| 부서 교역자 | 부서 담당 교역자 (한 명이 여러 부서 가능) | 담당 부서의 학생·반 관리, 교사 출결, 주일보고 작성·시트 작성 버튼, 통계, ch2ch 반영, 출석 링크 교체 | 교역자 계정 로그인 |
| 보고 담당 교역자 | 교육2부 부서 담당 | 담당 부서의 주일보고 특이사항 입력 | 교역자 계정 로그인 |
| 교사 | 각 부서 선생님 | 자기 부서 모든 반의 출석·사유 입력, 새 친구 등록(이름·생년월일·성별) | 로그인 없음 (부서 출석 링크) |

## 기능 요구사항

구현 단계는 아래 "구현 단계"를 따릅니다.

### 1. 설정 (교역자)

- **교육부·부서 관리**: 교육부(교육1부·교육2부)와 부서를 만들고 이름·종류(교회학교 / 보고 전용)·예배 시간·대상 나이·표시 순서·진급할 다음 부서를 정합니다. 부서 신설·폐지·통합·분리를 지원하고, 폐지한 부서는 지우지 않고 숨겨 기록을 보존합니다.
- **학년 설정**: 부서별 학년(이름·순서·ch2ch 하위 이름·기본 연령). 통합 부서처럼 학년이 없는 부서도 지원합니다.
- **반 설정**: 부서별 반(이름·순서). 반은 출석 화면의 묶음일 뿐이며, 반이 없는 학생은 "미배정"으로 보입니다.
- **ch2ch 대응**: 부서의 ch2ch 교육기관 이름(예: "[덕소]소년부")과 학년의 ch2ch 하위 이름(예: "4학년"). 교적 동기화와 북마클릿이 함께 씁니다.
- **주일보고서 시트**: 연도별 구글 시트 주소(2027년 시트는 새로 만듦), 평균 계산에서 뺄 주일(명절 등) 목록.

### 2. 교사 출석 (부서 출석 링크)

- 부서마다 추측할 수 없는 긴 주소를 만들어 단톡방·QR로 공유합니다. 열면 그 부서 출석부가 뜨고, 반(미배정 포함)을 골라 체크합니다. 홈 화면에 추가해 두면 다음 주부터 바로 열립니다.
- **날짜**: 한국 시간 기준 "그 주 일요일"이 기본으로 잡히고, 교사가 다른 날짜로 바꿀 수 있습니다(지난 주일을 늦게 입력하는 경우 등). 서버는 UTC이므로 날짜 계산은 반드시 한국 시간(Asia/Seoul) 기준으로 합니다.
- **바꾼 학생만 저장**: 저장 시 교사가 실제로 바꾼 학생의 출석만 보냅니다. 여러 선생님이 동시에 같은 부서를 열어도 서로의 입력을 지우지 않습니다(같은 학생을 둘이 고치면 나중 저장이 이김).
- **새 친구 등록**: 이름·생년월일·성별(반 선택 가능)을 입력하면 "새친구" 상태의 학생으로 바로 만들어지고 그날 출석으로 기록됩니다. 같은 부서에 같은 이름이 있으면 경고합니다. 교역자가 확인하면 "재학"으로 바뀝니다.
- 휴대폰 한 손 입력 기준, 저장 버튼 하나, 마지막으로 본 반 기억.
- 링크로는 출석·사유 저장과 새 친구 등록만 가능하고, 개인정보는 보지 못합니다(새 친구의 생년월일은 쓰기만 가능).

### 3. 학생 관리와 교적 동기화 (교역자)

- 부서별 학생 목록·수정·반 지정·부서 이동·전학 처리. "교적 등록 필요" 체크박스를 직접 켜고 끌 수 있습니다.
- **교적 동기화**: ch2ch에서 내려받은 교적 명단 파일로 우리 DB를 교적에 맞춥니다(아래 "교적 동기화" 상세).
- **반 편성 가져오기**: 새 학년도 반 편성표(엑셀)로 반을 일괄 교체. 바뀌는 학생·못 찾은 이름을 미리보기.
- **연말 진급**: 부서 안에서 학년을 올리고, 마지막 학년은 다음 부서 첫 학년으로 이동, 고등부 마지막 학년은 졸업. 학년이 없는 부서(통합 부서)는 생년월일 기준 대상자를 보여 주고 교역자가 개별 지정. 미리보기 후 한 번에 실행, 한 해에 한 번만, 이동 이력 저장.

### 4. 교사 명단과 교사 출결 (교역자)

- 부서별 교사 명단(이름, 담당 반, 역할, 연락처). 교적 파일의 교사 행으로 갱신하거나 직접 입력합니다.
- 매주 기본값은 모두 출석, 결석한 교사만 체크하고 사유(예: 출산, 간호)를 적습니다. 교사별 출석률도 볼 수 있습니다.

### 5. 주일보고 (교역자)

- **부서별 주일보고 화면**: 교사 출결, 헌금(부서 합계 금액), 예배 주제(본문/설교제목), 이번 주 교육활동, 다음 주 교육활동, 특이사항/건의사항을 입력합니다. 학생 재적·출결·평균·최대는 같은 화면에 자동으로 보입니다. 지난주 "다음 주 교육활동"을 이번 주 "이번 주 교육활동"에 미리 채웁니다.
- **보고 전용 부서**(교육2부): 특이사항만 입력합니다.
- **"주일보고서 작성" 버튼**: 출석과 입력을 마친 담당 교역자가 누르면, 앱이 그 주 시트 탭에 **한 번만** 씁니다(아래 "주일보고서 시트 작성").
- 전체 교역자는 부서별 작성 현황(작성 전 / 시트 작성 완료)과 교육부 전체 보고서를 한 화면에서 봅니다. 누가 언제 고쳤는지 남습니다.

### 6. 통계 (교역자)

- 부서별 출석 관리 표(주별 합계 줄 포함), 출석 통계, 52주 출석 그룹(A~E, 모든 부서 같은 기준), 관심 필요 학생. 모두 현재 부서 기준.
- 전체 대시보드: 교육1부 부서별 주별 출석 인원·출석률·관심 필요 학생 수.
- 출석 입력 현황: 주일 오후까지 입력하지 않은 반을 교역자에게 표시.

### 7. ch2ch 반영 (교역자)

- 북마클릿과 출석 조회 API는 **지금 방식을 유지**합니다(공개 API, ch2ch.or.kr만 CORS 허용).
- 다른 부서로 넓힐 때는 ch2ch 화면의 교육기관 이름·하위 이름을 함께 보내 부서·학년을 찾습니다(지금은 학년 숫자만 보냄). 학년 숫자만 보내는 기존 호출은 소년부로 처리해 기존 북마클릿이 계속 동작하게 합니다.

## 주일보고서 시트 작성

담당 교역자가 "주일보고서 작성" 버튼을 누를 때 앱이 그 주 탭에 한 번 씁니다. 실시간으로 계속 쓰지 않습니다. 2027년 시트는 새로 만들고, 시트의 행 구성과 숫자는 앱이 정합니다.

- **원본은 앱**: 부서·연령 행은 부서 설정에서 만들어지므로 부서가 바뀌어도 양식을 고칠 필요가 없습니다. 기존 시트의 재적 탭 수식은 앱이 없어서 만든 것이므로 쓰지 않고, 앱이 자동 계산한 값을 씁니다.
- **버튼을 누르면**:
    1. 그 해 시트에 "MM.DD" 탭이 없으면 만듭니다(열: 부서, 연령, 학생재적, 학생출결, 평균출석, 최대출석, 교사재적, 교사출결, 교사결석사유 이름·사유, 헌금, 예배 주제, 이번 주·다음 주 교육활동, 특이사항/건의사항, 하단에 교육2부 특이사항, 총합, 연령 합계).
    2. 누른 부서의 행과, 모든 부서를 합한 총합·연령 합계 행을 DB 값으로 다시 씁니다. 다른 부서의 행은 건드리지 않습니다.
    3. "재적" 탭(부서·연령별 재적, 주별 출석, 평균·최대)을 앱 계산값으로 다시 씁니다.
    4. 한 번의 시트 요청(batchUpdate)으로 처리하고, 성공하면 "시트 작성 완료"와 시각을 남깁니다. 실패하면 오류를 보여 주고 다시 누를 수 있습니다. 다시 누르면 그 부서 행을 덮어씁니다(수정 반영).
- **숫자 계산**:
    - 연령 = 생년월일 기준 **세는 나이**(2026년 시트의 연령 행과 일치: 소년부 4학년 = 11세). 생년월일이 없으면 학년의 기본 연령, 그것도 없으면 "연령 미상" 행.
    - 학생재적 = 그 부서 재학·휴학 학생 수(연령별), 학생출결 = 그 날짜 출석 인원(연령별), 새친구 행 = "새친구" 상태 학생의 출석 인원.
    - 평균 = 그 해 기록이 있는 주의 평균(설정한 명절 주일 제외), 최대 = 그 해 최대.
    - 교사재적 = 활동 중 교사 수, 교사출결 = 재적 − 결석, 결석사유 = 결석 교사 이름·사유.
- **권한**: 시트에는 앱 전용 구글 서비스 계정을 편집자로 추가합니다. 공유 드라이브가 외부 계정 공유를 막는 경우 관리자 설정 확인이 필요합니다. 시트에는 생년월일·연락처 같은 개인정보를 쓰지 않습니다.

## 교적 동기화

부서마다 흩어진 명단을 교적(ch2ch)에 맞추되, 교적에 아직 없는 학생은 지우지 않고 "교적 등록 필요"로 표시해 등록을 챙깁니다.

**교적 명단 파일**: ch2ch 교인관리에서 내려받은 .xls 파일로, 실제로는 HTML 표입니다(엑셀 라이브러리가 아니라 HTML로 읽어야 함). 2026년 11월 소년부 파일은 81행(학생 68명 + 교사 13명)이고, 열은 번호, 반(실제로는 "4학년" 같은 학년, 교사는 "교사"), 교사, 교사휴대폰, 이름, 가족관계, 성별, 생일(YYYYMMDD), 양음, 휴대폰, 주소, 행정분류(교인·새가족), 학교, 학년(비어 있음), 신급, 부모(이름·관계·연락처·[직분]/교구/구역, 보호자 2명이면 이어서), 출석시작일, 출/결, 출석율입니다. **반 번호와 ch2ch 교인번호는 없습니다.** 다른 부서 파일의 "반" 값 형식은 부서별 샘플로 확인해야 합니다.

| 경우 | 처리 |
| --- | --- |
| 교적과 우리 DB 둘 다 있음 | 교적 기준으로 성별·학년과 개인정보(생일·휴대폰·주소·보호자)를 맞추고 "교적 등록 필요" 해제 |
| 교적에만 있음 | 새 학생으로 추가(반 미배정). 교사 화면에 "미배정"으로 보여 바로 출석 가능 |
| 우리 DB에만 있음 | 지우지 않고 "교적 등록 필요" 체크. ch2ch에 등록하면 다음 동기화 때 자동 해제, 교역자가 직접 끄기도 가능 |
| 교사 행 | 교사 명단으로 저장(새 교사 추가, 이름이 같으면 연락처 갱신) |

- **연결 기준**: 파일의 "반" 값 → 학년의 ch2ch 하위 이름으로 부서·학년을 찾고, 그 안에서 이름으로 연결합니다. 이름 끝 영문 대문자 차이(강세원B ↔ 강세원)는 연결하고, 후보가 여럿이면 건너뛰고 미리보기에 표시합니다(기존 `src/lib/student-matching.ts` 규칙 재사용).
- **보호자**: 교적에는 부·모 대신 세대주·처 같은 관계로만 나오므로 "보호자 1·2(이름·관계·연락처)"로 저장하고, 시트에서 가져온 부·모 칸은 그대로 둡니다.
- **안전장치**: 미리보기 후에만 반영하고, 반영은 한 트랜잭션으로 처리하며 작업 기록을 남깁니다. 개인정보가 담긴 원본 파일은 저장소에 올리지 않습니다(.xls·.xlsx·.csv는 .gitignore에 등록됨).

**지금 차이 (2026년 11월, 소년부)**: 우리 DB 4학년 25명·5학년 26명·6학년 29명, 교적 24명·18명·26명. 5학년 8명 차이는 첫 동기화 미리보기에서 확인합니다.

1. Neon 개발 브랜치에서 모든 마이그레이션을 먼저 실행해 확인합니다.
2. 교육부·부서·학년·반을 만들고, 기존 학생 80명을 소년부로, 학년 문자열(4.믿음 등)을 학년으로, 반 번호를 반으로 연결합니다.

4. 새 칸을 쓰는 코드는 마이그레이션을 운영 DB에 적용한 **뒤에** 배포합니다.

## 보안·개인정보

선생님 출석 화면은 로그인 없이 열리므로, 링크로 할 수 있는 일을 "그 부서 출석 입력과 새 친구 등록"으로 좁히고 나머지는 모두 교역자 계정 뒤에 둡니다.

- **링크 범위는 서버가 강제**: 링크 토큰으로 부서를 찾고, 그 부서 학생의 이름·반과 출석만 돌려주며, 출석·사유·새 친구만 저장합니다. 다른 부서, 개인정보 조회, 학생 수정·삭제는 거부합니다.
- **링크 교체**: 유출되면 교역자가 새 링크로 바꾸고 이전 링크는 즉시 막힙니다. 학년도마다 교체를 권장합니다. 링크 저장 요청에도 횟수 제한을 둡니다.
- **변경 기록**: 모든 출석 변경을 기록해 잘못된 입력을 교역자가 되돌릴 수 있습니다.
- **교역자 계정**: 교역자 화면과 API는 로그인 필수, 담당 부서만 접근합니다. "누가, 언제, 어느 부서, 몇 명"을 기록합니다. 로그인이 생기면 공용 관리자 비밀번호와 임시 비밀번호는 없앱니다(지금의 비밀번호 대입 차단은 그때까지 유지).
- **유지하는 공개 API**: ch2ch 북마클릿용 출석 조회(`/api/ch2ch`)는 지금처럼 공개합니다. 학생 이름과 출석이 조회될 수 있다는 점은 감수합니다.
- **개인정보**: 생년월일·연락처·주소는 별도 테이블에 두고, 담당 교역자만 가져오기·추출합니다. 시트·링크 화면에는 나가지 않습니다.
- **동의와 보관 기간 (확인 필요)**: 대부분 14세 미만이라 보호자 동의가 필요할 수 있습니다. 동의서 양식과 졸업·전출 학생 자료 파기 시점을 정해야 하며, 법적 요건은 전문가 확인이 필요합니다.
- **바깥 데이터 정리**: 부서마다 쓰던 구글 시트는 앱으로 옮긴 뒤 공유를 "제한됨"으로 바꾸거나 보관 처리합니다. 공개 GitHub 저장소는 비공개로 바꿉니다.

## 운영·인프라

학생 300명, 주 1회 출석이면 기록은 연 약 15,600건으로 지금 구조(Vercel + Neon)로 충분합니다.

- **개발·운영 DB 분리**: Neon 브랜치로 개발용 DB를 만들고 개인정보는 빼거나 가짜 값으로 바꿉니다.
- **배포**: Vercel 프로젝트는 하나만 두고(중복 프로젝트 삭제), 미리보기 배포는 보호를 켭니다. 마이그레이션은 배포 전에 적용합니다.
- **시트 쓰기**: 버튼을 누를 때만 한 번 쓰므로 예약 작업이나 대기열이 필요 없습니다(Vercel 무료 요금제로 가능).
- **백업**: Neon 시점 복구를 기본으로, 분기마다 부서별 출석을 엑셀로 내려받아 보관합니다.
- **운영 담당자**: 앱 관리자 1명이 매년 반복되는 일(부서 개편 반영, 교역자 계정, 연말 진급, 반 편성, 새해 시트 등록)을 맡고 절차를 README에 남깁니다.

## 구현 단계

날짜보다 순서가 중요합니다. 각 단계가 끝나면 그대로 운영에 쓸 수 있게 나눕니다.

1. **준비**: Neon 개발 브랜치, 교역자 로그인 방식 확정, 교육1부 부서·학년·반 설정값 수집.
2. **기반**: 교육부·부서·학년·반 모델과 소년부 이관, 교역자 로그인과 담당 부서 권한, 부서 출석 링크(한국 시간 날짜·날짜 변경·바꾼 학생만 저장·새 친구 등록), 부서별 Admin(출석 관리·통계·학생 관리).
3. **명단**: 교적 동기화(ch2ch 대응 설정 포함), 나머지 부서 온보딩, 반 편성 가져오기, 연말 진급·부서 이동.
4. **주일보고**: 교사 명단·교사 출결, 부서별 주일보고 입력(헌금 포함), 교육2부 보고 전용 부서, 주일보고서 작성 버튼(시트 탭·재적 탭 자동 작성).
5. **확장**: 전체 대시보드, 출석 입력 현황, ch2ch 북마클릿의 다른 부서 지원.
