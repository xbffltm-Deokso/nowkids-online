# 교회학교 8개 부서 확장 PRD

2026-11-14 기준 · 원본 문서: Claude Docs "교회학교 8개 부서 확장 PRD" (이 파일은 다른 컴퓨터에서 이어서 작업하기 위한 사본)

## 배경과 목표

2027년 첫 주일부터 교회학교 8개 부서가 하나의 앱으로 출석 체크, 통계, ch2ch 반영, 진급을 처리하는 것이 목표입니다. 지금 앱은 소년부 한 부서에 맞춰져 있어, 부서 개념·권한·설정을 새로 넣는 구조 개편이 필요합니다.

**왜 확장하나**

- 부서마다 구글 시트, ch2ch 수기 입력, 종이 출석부가 섞여 있어 교회학교 전체 출석 현황을 한눈에 볼 수 없습니다.
- 소년부에서 검증한 흐름(교사 출석 체크 → 관리자 통계 → ch2ch 분기 반영 → 연말 진급)은 모든 부서가 똑같이 반복합니다.
- 아동 개인정보가 여러 시트에 흩어져 있고 일부는 링크 공개 상태라, 한곳에서 권한을 두고 관리할 필요가 있습니다.

**성공 기준 (안)**

| 기준 | 목표치 (안) | 측정 |
| --- | --- | --- |
| 부서 사용률 | 8개 부서 모두 매주 출석 입력 | 주일별 기록이 있는 부서 수 |
| 출석 입력 완료율 | 주일 당일 재적 대비 기록 90% 이상 | 출석 통계의 기록 인원 / 재적 |
| ch2ch 반영 시간 | 부서당 분기 1회, 학년별 북마클릿 실행으로 끝남 | 부서 담당자 확인 |
| 개인정보 관리 | 개인정보가 담긴 공개 링크 시트 0개 | 구글 드라이브 공유 설정 점검 |

## 현재 시스템 현황 (As-Is)

현재 앱(Next.js + Neon Postgres, Vercel 배포)은 소년부 전용이며, 아래 항목이 모두 "부서가 하나"라는 가정 위에 만들어져 있습니다.

| 영역 | 현재 | 8개 부서로 확장 시 문제 |
| --- | --- | --- |
| 학년·반 | 코드에 4.믿음·5.소망·6.사랑, 1~4반 고정 (`src/utils/grades.ts`) | 부서마다 학년·반 수와 이름이 다름. 관리 화면에서 설정해야 함 |
| 학생 ID | 일부는 `학년_반_번호_이름`, 새 학생은 UUID | 부서 간 동명이인, 부서 이동 시 혼동 |
| 접근 권한 | 페이지·조회 API 공개, 관리자 비밀번호 1개 | 부서별 분리 불가. 학생 약 300명 명단이 주소만 알면 공개됨 |
| 출석 모델 | 일요일 1회, 출석/결석 + 사유 | 모든 부서가 일요일이지만 10시·12시 예배로 나뉘고, 같은 나이가 두 부서에 있음 |
| 통계·출석그룹 | 전체 재적 기준 52주 계산 | 부서별 재적·출석부 작성 주 기준으로 나눠야 함 |
| ch2ch 연동 | 북마클릿, ch2ch "4학년" ↔ 우리 "4.믿음"을 숫자로 대응 | 부서마다 ch2ch 교육기관·하위 이름이 다름. 대응표 필요 |
| 진급 | 4→5→6학년, 6학년은 "진급" 상태로 빠짐 | 부서 간 이동(예: 소년부 6학년 → 중등부 1학년)이 없음 |
| 개인정보 | 별도 테이블, 비밀번호로 가져오기·추출 | 누가 어느 부서 개인정보를 보는지 구분 불가 |
| 개발 환경 | 로컬 개발도 운영 DB 사용 | 시험이 실제 데이터를 바꾸거나 개인정보를 노출할 위험 |

전체 학생 수 약 300명은 2026년 11월 기준 추정치입니다. 소년부가 그중 약 80명입니다.

## 범위와 사용자·권한

선생님은 로그인 없이 부서 출석 링크로 그 부서 모든 반의 출석을 체크하고, 학생·설정·개인정보 등 DB 수정은 교역자 계정만 할 수 있게 합니다.

**대상 부서 (8개, 전체 학생 약 300명)**: 통합미취학부(2~7세), 영유아부, 유치부, 통합아동부(8~13세), 유년부, 소년부, 중등부, 고등부. ch2ch에는 "[덕소]소년부", "[세움] 청소년부"처럼 지구 이름이 붙어 있어, 실제 부서 목록과 ch2ch 교육기관 이름을 함께 확정해야 합니다.

통합미취학부·통합아동부는 **10시 예배**, 나머지 6개 부서는 **12시 예배** 부서입니다. 같은 나이라도 예배 시간에 따라 부서가 나뉘므로, 나이만으로 부서를 자동 배정하면 안 되고 부서마다 학년 구성과 진급 규칙을 따로 정해야 합니다. 가정 사정으로 10시·12시 부서를 옮기는 학생도 있을 수 있어 학년 중간의 부서 이동도 필요합니다.

**범위에서 빠지는 것**: 장년부 출석, 헌금·회계, 문자 발송, 학부모용 화면.

| 역할 | 누구 | 할 수 있는 일 | 접속 방법 |
| --- | --- | --- | --- |
| 전체 교역자 | 교육 담당 교역자 | 모든 부서의 DB 수정(부서·학년·반 설정, 학생 관리, 진급, 개인정보, 기록 삭제), 교역자 계정 관리, 전체 통계 | 교역자 계정 로그인 |
| 부서 교역자 | 부서 담당 전도사 | 자기 부서의 DB 수정, 통계, ch2ch 반영, 부서 출석 링크 교체 | 교역자 계정 로그인 |
| 교사 | 각 부서 선생님 전체 | 자기 부서 모든 반의 출석·사유 입력, 새 친구 이름 남기기 | 로그인 없음 (부서 출석 링크) |

**접속 방식**

1. **선생님: 부서 출석 링크**: 부서마다 추측할 수 없는 긴 주소를 만들어 교사 단톡방이나 QR로 공유합니다. 열면 바로 그 부서 출석부가 뜨고, 반을 골라 체크합니다. 휴대폰 홈 화면에 추가해 두면 다음 주부터 한 번에 열립니다.
2. **교역자: 개인 계정 로그인**: DB를 고치는 모든 기능은 교역자 계정(교회 구글 계정 권장)으로 로그인해야 하고, 누가 무엇을 했는지 기록합니다. 지금의 공용 관리자 비밀번호는 없앱니다.

## 기능 요구사항

2027년 1월 시작에는 P0이 모두 필요하고, P1은 1분기 ch2ch 반영(3월 말) 전까지, P2는 그 이후입니다. 소년부에 이미 있는 기능은 "부서 단위로 나누기"가 대부분입니다.

**부서 구성은 바뀐다는 전제**: 2027년에 통합미취학부·통합아동부가 폐지되고 미취학 1부·2부로 재편될 수 있습니다. 부서·학년·연령·반은 코드에 넣지 않고 모두 교역자 화면에서 설정합니다. 부서 신설·폐지·통합·분리와 학생 일괄 이동을 지원하고, 폐지한 부서는 지우지 않고 숨겨 지난 출석 기록과 통계를 그대로 보존합니다. 주일보고서도 이 설정에서 만들어져 부서가 바뀌어도 양식을 고칠 필요가 없어야 합니다.

| P2 | 출석 입력 현황 | 주일 오후까지 입력하지 않은 반을 교역자에게 표시 |
| P2 | 부서 간 이동 이력 | 한 학생의 부서·학년 이력과 연도별 출석률을 이어서 보기 |

## 주일보고서 연동

출석 체크가 끝나면 앱이 주일보고서의 부서·연령별 학생출결과 재적·평균·최대 출석을 계산하고, 등록해 둔 구글 시트에 그 주 탭을 만들어 채웁니다. 현재 시트는 "2026 지금세대교육부 주일보고서"(공유 드라이브)입니다.

**지금 방식**: 매주 "양식" 탭을 복사해 날짜 탭을 만들고, 부서×연령 행마다 학생출결을 손으로 입력합니다. 재적은 "재적" 탭에 직접 적고, 평균·최대 출석은 수식으로 날짜 탭을 모읍니다. 부서와 연령 행이 양식과 수식에 고정되어 있어, 부서가 바뀌면 양식·재적 탭·수식을 모두 고쳐야 합니다.

양식 구조(조사 결과): 열은 부서, 연령, 학생재적, 학생출결, 평균출석, 최대출석, 교사재적, 교사출결, 교사결석사유(이름·사유), 헌금, 예배 주제, 이번 주 교육활동, 다음 주 교육활동, 특이사항/건의사항. 부서마다 연령별 행 + 새친구 + 합계 행이 있고, 하단에 총합·교역자동정·연령 합계가 있습니다. 소년부 재적은 이미 다른 시트에서 IMPORTRANGE로 가져오고 있습니다.

| 보고서 항목 | 연동 후 | 근거 |
| --- | --- | --- |
| 학생재적 | 자동 | 부서·연령별 재적 학생 수 |
| 학생출결, 새친구 | 자동 | 그 주일 출석 체크, 새 친구 이름 |
| 평균·최대 출석, 연령 합계, 총합 | 자동 | 앱의 전체 출석 이력 (명절 제외 규칙 포함) |
| 교사재적·교사출결·결석사유 | 교역자 입력 (앱) | 교사 명단을 앱에 두고 결석자만 체크 |
| 헌금, 예배 주제, 교육활동, 특이사항 | 교역자 입력 (앱) | 부서별 주일보고 화면 |

**연동 방식 (권장)**

1. 보고서의 원본은 앱이 갖습니다. 부서·연령 행은 부서 설정에서 만들어져, 부서가 바뀌어도 보고서가 따라서 바뀝니다.
2. 교역자가 구글 시트 주소를 설정에 등록하고, 그 시트에 앱 전용 구글 계정(서비스 계정)을 편집자로 추가합니다.
3. **실시간 반영**: 그 주 첫 출석이 들어오면 앱이 "MM.DD" 탭을 지금 양식과 같은 열 순서로 만들고, 이후 출석이 저장될 때마다 그 부서·연령 행의 학생출결·새친구·합계·총합만 다시 씁니다. 10시·12시 입력이 몰릴 때는 약 1분 단위로 모아 한 번에 쓰고(구글 시트 API 쓰기 횟수 제한 대비), 사람이 적는 칸(교사출결·헌금·특이사항 등)은 건드리지 않습니다. 시트 쓰기가 실패하면 "시트 반영 대기"로 표시하고 자동 재시도하며, "지금 시트에 반영" 버튼도 둡니다. 출석은 앱에 먼저 저장되므로 시트 오류로 기록이 사라지지 않습니다.
4. 연령별 행을 위해 학년마다 보고서 연령(예: 소년부 4학년 = 11세)을 설정하고, 학년이 없는 부서는 생년월일로 서버에서 계산합니다(생년월일은 화면·시트에 나가지 않음).

대안으로, 앱에 구글 계정을 주지 않고 시트가 앱의 보고서 주소를 `IMPORTDATA`로 가져오는 방법도 있습니다. 설정은 간단하지만 구글이 대략 1시간 주기로만 새로 가져와 실시간 반영이 안 되고, 주소에 비밀 토큰을 넣어야 하며, 부서가 바뀌면 시트 수식을 다시 고쳐야 합니다.

**확인이 필요한 것**: 보고서 연령이 세는 나이인지, 같은 연령 행이 여러 개인 것(예: 소년부 11세 3행)이 반별 행인지, 평균에서 빼는 명절 주일이 언제인지.

## 교적 동기화

부서마다 흩어져 관리하던 명단을 교적(ch2ch)에 맞추되, 교적에 아직 없는 학생은 지우지 않고 "교적 등록 필요"로 표시해 등록을 챙깁니다.

**교적 명단 파일**: ch2ch 교인관리에서 내려받은 .xls 파일로, 실제로는 HTML 표입니다(엑셀 라이브러리가 아니라 HTML로 읽어야 함). 2026년 11월 소년부 파일은 81행(학생 68명 + 교사 13명)이고, 열은 번호, 반(실제로는 "4학년" 같은 학년, 교사는 "교사"), 교사, 교사휴대폰, 이름, 가족관계, 성별, 생일(YYYYMMDD), 양음, 휴대폰, 주소, 행정분류(교인·새가족), 학교, 학년(비어 있음), 신급, 부모(이름·관계·연락처·[직분]/교구/구역, 보호자 2명이면 이어서), 출석시작일, 출/결, 출석율입니다. **반 번호와 ch2ch 교인번호는 없습니다.**

| 경우 | 처리 |
| --- | --- |
| 교적과 우리 DB 둘 다 있음 | 교적 기준으로 성별·학년과 개인정보(생일·휴대폰·주소·보호자)를 맞추고 "교적 등록 필요" 해제 |
| 교적에만 있음 | 새 학생으로 추가, 반은 "미배정". 교사 화면에도 "미배정" 반으로 보여 바로 출석 가능, 반 편성 때 지정 |
| 우리 DB에만 있음 | 지우지 않고 "교적 등록 필요" 체크. ch2ch에 등록하면 다음 동기화 때 자동 해제, 교역자가 직접 끄기도 가능 |
| 교사 행 | 교사 명단으로 저장해 주일보고서의 교사재적·교사출결에 사용 |

- **연결 기준**: 교인번호가 없어서 이름 + 학년으로 연결합니다. 이름 끝 영문 대문자 차이(강세원B ↔ 강세원)는 연결하고, 후보가 여럿이면 건너뛰고 미리보기에 표시합니다. (기존 `src/lib/student-matching.ts` 규칙 재사용)
- **보호자**: 교적에는 부·모 대신 세대주·처 같은 관계로만 나오므로 "보호자 1·2(이름·관계·연락처)"로 저장하고, 시트에서 가져온 부·모 칸은 그대로 둡니다.
- **안전장치**: 미리보기 후에만 반영하고, 반영은 한 트랜잭션으로 처리하며 작업 기록을 남깁니다. 개인정보가 담긴 원본 파일은 저장소에 올리지 않습니다(.xls·.xlsx·.csv는 .gitignore에 등록됨).

**지금 차이 (2026년 11월, 소년부)**

| 학년 | 우리 DB | 교적 |
| --- | --- | --- |
| 4학년 | 25명 | 24명 |
| 5학년 | 26명 | 18명 |
| 6학년 | 29명 | 26명 |

5학년의 8명 차이는 첫 동기화 미리보기에서 누구인지 확인해야 합니다.

**구현 메모**: 필요한 DB 변경은 `students.needs_registration`(boolean, 기본 false)과 `student_private`의 `guardian1·2` 이름·관계·연락처 칸입니다. 반 번호 0을 "미배정"으로 쓰되, 조회 API의 `classNum=0`은 "전체 반"이므로 화면의 반 선택에서는 따로 구분합니다(예: 선택값 -1 = 미배정). 칸 추가 마이그레이션은 새 코드를 배포하기 **전에** 운영 DB에 적용해야 합니다.

출석 기록과 개인정보는 학생을 통해 부서가 정해지므로 구조를 바꾸지 않습니다. 이관 순서는 아래와 같습니다.

1. 8개 부서를 만들고, 기존 학생 80명을 소년부로 지정합니다.
2. 지금의 학년 문자열(4.믿음 등)을 학년 테이블로 옮기고 학생이 그것을 참조하게 합니다.
3. 학생 ID는 그대로 두고 새 학생부터 UUID를 씁니다(이미 적용됨).
4. 모든 마이그레이션은 Neon 개발 브랜치에서 먼저 실행해 확인한 뒤 운영에 적용합니다.

## 보안·개인정보

선생님 출석 화면은 로그인 없이 열리므로, 링크로 할 수 있는 일을 "그 부서 출석 입력"으로 좁히고 나머지는 모두 교역자 계정 뒤에 둡니다.

- **부서 출석 링크의 범위**: 링크로는 그 부서 학생의 이름·반과 출석만 보고, 출석·사유·새 친구 이름만 저장합니다. 다른 부서, 개인정보, 학생 수정·삭제는 서버가 거부합니다. 화면에서 숨기는 것만으로는 막을 수 없습니다.
- **링크 교체**: 링크가 외부로 퍼지면 교역자가 새 링크로 바꾸고, 이전 링크는 즉시 막힙니다. 학년도가 바뀔 때마다 교체를 권장합니다.
- **출석 저장 기록**: 링크로 저장한 출석은 저장 시각과 이전 값을 남겨, 잘못 입력되거나 장난이 있으면 교역자가 되돌릴 수 있게 합니다. 링크 저장 요청에도 횟수 제한을 둡니다.
- **교역자 계정**: DB 수정과 개인정보는 개인 계정으로 로그인한 교역자만 할 수 있고, "누가, 언제, 어느 부서, 몇 명"을 기록합니다. 지금의 공용 관리자 비밀번호와 임시 비밀번호는 없앱니다.
- **개인정보 접근**: 생년월일·연락처·주소는 지금처럼 별도 테이블에 두고, 담당 교역자만 자기 부서 것을 가져오기·추출합니다.
- **남는 위험**: 링크를 아는 사람은 그 부서 학생 이름과 출석을 볼 수 있습니다. 이름 외의 정보는 링크 화면에 나오지 않게 해 영향을 줄입니다.
- **동의와 보관 기간 (확인 필요)**: 대부분 14세 미만이라 보호자 동의가 필요할 수 있습니다. 교회의 동의서 양식과 졸업·전출 학생 개인정보 파기 시점을 정해야 합니다. 법적 요건은 전문가 확인이 필요합니다.
- **바깥 데이터 정리**: 부서마다 쓰던 구글 시트는 앱으로 옮긴 뒤 공유를 "제한됨"으로 바꾸거나 보관 처리합니다. 공개 GitHub 저장소는 비공개로 바꿉니다.

## 운영·인프라

학생 300명, 주 1회 출석이면 기록은 연 약 15,600건(300명 × 52주)으로, 지금 구조(Vercel + Neon)로 충분합니다. 더 큰 과제는 운영 안전장치입니다.

- **개발·운영 DB 분리**: Neon 브랜치로 개발용 DB를 만들고 개인정보는 빼거나 가짜 값으로 바꿉니다. 지금처럼 로컬 개발이 운영 DB를 쓰면 8개 부서 데이터가 시험 중에 바뀔 수 있습니다.
- **배포**: Vercel 프로젝트는 하나만 두고(중복 프로젝트 삭제), 미리보기 배포는 Vercel 보호(로그인 필요)를 켭니다. 마이그레이션은 배포 전에 적용합니다.
- **백업**: Neon의 시점 복구를 기본으로 두고, 분기마다 부서별 출석 기록을 엑셀로 내려받아 보관합니다. 복구 가능 기간은 요금제에 따라 다르니 확인이 필요합니다.
- **비용 (확인 필요)**: Vercel·Neon 무료 요금제 한도 안에서 운영될 것으로 보이지만, 로그인·미리보기 보호 등 일부 기능은 유료 요금제가 필요할 수 있습니다.
- **예배 시간대 부하**: 10시·12시에 교사들이 동시에 입력하더라도 수십 명 수준이라 문제가 없습니다. 다만 출석 그룹 계산은 부서별로 나눠 필요한 부서만 계산합니다.
- **운영 담당자**: 앱 관리자 1명이 매년 반복되는 일(부서·권한 정리, 연말 진급, 반 편성)을 맡고, 절차를 README에 남깁니다.

## 다른 컴퓨터에서 이어서 작업할 때

- 이 저장소를 받은 뒤 `.env.local`에 `DATABASE_URL`(Neon), `APP_PASSWORD`를 넣어야 합니다(저장소에는 없음).
